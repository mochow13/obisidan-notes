## What is Bloom Filters
A probabilistic data structure that tries to answer a simple question—*have I seen this before?* It basically space efficiently checks for existence of an element while being prone to **false positives**.

The idea behind bloom filters is pretty simple but elegant:

- Have $k$ number of hash functions
- There is a single bit-array (where each index can store $0$ or $1$ only) of size $m$
- When adding an element to the filter, hash it using all $k$ hash functions and setting the corresponding bit to $1$ in the same bit-array
- To check existence of an element, hash it through all hash functions and check the corresponding bit position in the bit-array
	- If all positions are $1$, then *maybe* the element already exists—this could be false positive
	- If at least one hash returns $0$, then the element **definitely does not exist**
- Why the first case can be false positive? Because there could be hash collisions between the new element with one or more other elements across the $k$ hash functions

Bloom filter can correctly say when an element doesn't exist but can raise false positive otherwise.
## Basic Implementation in Python

```python
# Generated by Gemini 3
import hashlib

class SimpleBloomFilter:
    def __init__(self, size, num_hashes):
        """
        :param size: The number of bits in the filter (m)
        :param num_hashes: The number of hash functions to use (k)
        """
        self.size = size
        self.num_hashes = num_hashes
        self.bit_array = [False] * size

    def _hashes(self, item):
        """
        Generates 'num_hashes' indexes for a given item.
        We use MD5 and add a salt to create multiple unique hashes.
        """
        indexes = []
        for i in range(self.num_hashes):
            # Create a unique salt for each hash iteration
            salted_item = f"{i}{item}".encode('utf-8')
            digest = hashlib.md5(salted_item).hexdigest()
            # Convert the hex hash to an integer and map it to our array size
            index = int(digest, 16) % self.size
            indexes.append(index)
        return indexes

    def add(self, item):
        """Sets the bits at the calculated indexes to True."""
        for index in self._hashes(item):
            self.bit_array[index] = True

    def __contains__(self, item):
        """
        Checks if an item is likely in the set.
        Returns False if definitely not present.
        Returns True if potentially present (probabilistic).
        """
        return all(self.bit_array[index] for index in self._hashes(item))

# --- Example Usage ---

# Initialize a filter with 100 bits and 5 hash functions
bf = SimpleBloomFilter(size=100, num_hashes=5)

# Add some items
bf.add("apple")
bf.add("banana")

print(f"Is 'apple' in the filter? { 'apple' in bf }")    # Expected: True
print(f"Is 'cherry' in the filter? { 'cherry' in bf }") # Expected: False (usually)
```

Note: in a good implementation, a proper `bitarray` will be used instead of an array which is less space efficient.

A more production level implementation will look like this:

```python
# Written by Gemini 3
import math
import mmh3
from bitarray import bitarray

class ProductionBloomFilter:
    def __init__(self, expected_items, false_positive_rate):
        """
        Calculates optimal size and hash count automatically.
        :param expected_items: (n) The number of items you plan to store
        :param false_positive_rate: (p) Your tolerance (e.g., 0.01 for 1%)
        """
        self.n = expected_items
        self.p = false_positive_rate
        
        # Math: m = -(n * ln(p)) / (ln(2)^2)
        self.size = int(-(self.n * math.log(self.p)) / (math.log(2)**2))
        
        # Math: k = (m/n) * ln(2)
        self.num_hashes = round((self.size / self.n) * math.log(2))
        
        # Initialize bit array with all zeros
        self.bit_array = bitarray(self.size)
        self.bit_array.setall(0)

    def add(self, item):
        """Hashes the item k times and sets bits to 1."""
        for seed in range(self.num_hashes):
            # mmh3 is much faster than hashlib for this purpose
            index = mmh3.hash(item, seed) % self.size
            self.bit_array[index] = 1

    def __contains__(self, item):
        """Returns True if item might be present, False if definitely not."""
        for seed in range(self.num_hashes):
            index = mmh3.hash(item, seed) % self.size
            if self.bit_array[index] == 0:
                return False
        return True

    def get_info(self):
        """Utility to see the stats of your filter"""
        return {
            "Size (bits)": self.size,
            "Size (KB)": round(self.size / 8 / 1024, 2),
            "Hash Functions": self.num_hashes,
            "Current Fill Rate": f"{(self.bit_array.count(1) / self.size) * 100:.2f}%"
        }

# --- Usage ---
# Store 1 million items with 0.1% error rate
bf = ProductionBloomFilter(expected_items=1_000_000, false_positive_rate=0.001)

bf.add("user_12345")
print(bf.get_info())
print(f"Check 'user_12345': {'user_12345' in bf}")
print(f"Check 'user_99999': {'user_99999' in bf}")
```

## False Positive Math
Interestingly, we can calculate how many hash functions and size of each hash function needed based on expected element size and false positive tolerance level. There is interesting math involved. The above code implements the formula to decide on the bloom filter parameters.

Let's try to derive the math.

Assume we have $m$ bit and $1$ hash function. The probability of a specific bit to be not selected after one element is inserted is:
$$\large 1 - \frac{1}{m}$$
Now there are $k$ hash functions. The probability of a specific bit remains $0$ is after we run the element through $k$ hashes: 
$$\large (1 - \frac{1}{m})^k$$
After inserting $n$ elements, the probability that the specific bit still remains $0$ (after $n*k$ operations) is:
$$\large (1 - \frac{1}{m}) ^ {nk}$$
We can write the above as
$$\large((1 - \frac{1}{m})^m)^\frac{nk}{m}$$
If $m$ is large enough, $\large (1 - \frac{1}{m})^m$ approximates to $\large e^{-1}$. So we can write the probability that the specific bit remains $0$ after all $n$ elements inserted to the bloom filter as $\large e^{-\frac{nk}{m}}$. Which means the probability that the specific bit is set to $1$ equals $\large (1 - e^{-\frac{nk}{m}})$.

A false positive occurs when we check for an element that was never added but all $k$ bits checked by passing the element through the $k$ hash functions are already set to $1$. The probability of all these $k$ bits set to $1$ is:
$$\large p = (1 - e^{-\frac{nk}{m}})^k$$
where $p$ is the probability of false positive.

By doing some derivative magic, the above expression gives the minimum $p$ when
$$\large k = \frac{m}{n} ln(2)$$
Plugging it back to the $p$ will result in the minimum probability possible for a given $m$ and $n$:
$$\large p = (1 - e^{-\ln(2)})^k = (1 - \frac{1}{2})^k = 2^{-k} \approx (0.6185)^{m/n}$$
Now, what if we know $p$ and $n$—how to find optimal $k$ and $m$? We already know how to find $k$ if we have $m$ and $n$. We can also derive the formula for $m$ based on $\large p = (1 - e^{-\frac{nk}{m}})^k$.

Let's do this!

We have $\large p = ( 1 - e^{-\frac{nk}{m}})^k$ and $\large k = \frac{m}{n} \ln(2)$. Let's substitute $k$ in $p$.
$$p = \left( 1 - e^{-\frac{nk}{m}} \right)^{\frac{m}{n} \ln(2)}$$
Taking $ln$ on both sides:
$$\large \ln(p) = \frac{m}{n} \ln(2) \ln \left( 1 - e^{-\frac{nk}{m}} \right)$$
$$\large \frac{\ln(p)}{\ln(2)} = \frac{m}{n} \ln \left( 1 - e^{-\frac{n \cdot \frac{m}{n} \ln(2)}{m}} \right)$$

$$\large \frac{\ln(p)}{\ln(2)} = \frac{m}{n} \ln \left( 1 - e^{-\ln(2)} \right)$$

$$\large \frac{\ln(p)}{\ln(2)} = \frac{m}{n} \ln \left( 1 - e^{\ln(1/2)} \right)$$

$$\large \frac{\ln(p)}{\ln(2)} = \frac{m}{n} \ln \left( 1 - \frac{1}{2} \right)$$

$$\large \frac{\ln(p)}{\ln(2)} = \frac{m}{n} \ln \left( \frac{1}{2} \right)$$

$$\large \frac{\ln(p)}{\ln(2)} = -\frac{m}{n} \ln(2)$$

$$\large \text So, m = -\frac{n \ln(p)}{(\ln(2))^2}$$
## Double Hashing Optimisation
While the above is a fundamental implementation of bloom filter, there is an interesting optimisation which reduces the number of hash functions to just $2$. This is called Kirsch and Mitzenmacher optimisation.

The optimisation shows that we can only have $2$ hash functions and that's enough to set bit in $k$ positions.

```python
import math
import mmh3
from bitarray import bitarray

class BloomFilter:
    def __init__(self, n, fp_rate):
        # Calculate optimal size m and hash count k
        self.m = int(-(n * math.log(fp_rate)) / (math.log(2)**2))
        self.k = round((self.m / n) * math.log(2))
        
        # Initialize the bit array with all zeros
        self.bits = bitarray(self.m)
        self.bits.setall(0)
        
        print(f"Bloom Filter Initialized:")
        print(f" - Items (n): {n:,}")
        print(f" - Bits (m): {self.m:,} ({self.m / 8 / 1024 / 1024:.2f} MB)")
        print(f" - Hash Functions (k): {self.k}")

    def _get_hashes(self, item):
        """
        Double Hashing: 
        Generates k indices using only two 64-bit hash values.
        """
        h1, h2 = mmh3.hash64(str(item), signed=False)
        for i in range(self.k):
            # (h1 + i * h2) % m is the standard double hashing technique
            yield (h1 + i * h2) % self.m

    def add(self, item):
        for index in self._get_hashes(item):
            self.bits[index] = True

    def __contains__(self, item):
        for index in self._get_hashes(item):
            if not self.bits[index]:
                return False
        return True

# --- Execution for 10M items at 1% FPR ---
n = 10_000_000
p = 0.01

bf = BloomFilter(n, p)

# Test usage
bf.add("user_12345")
print(f"'user_12345' in filter? {'user_12345' in bf}")
print(f"'user_99999' in filter? {'user_99999' in bf}")
```

This optimisation greatly reduces computation overhead since we are not hashing $k$ times!

## Use Cases
1. Google Chrome uses a local bloom filter to check for malicious URL. If the URL doesn't exist in the filter, it's definitely safe. If it does, then Chrome makes a request to read from external storage to verify if the URL is safe.
2. Username availability can quickly be verified using a bloom filter.
3. Akamai CDN uses bloom filter to cache files only if it's requested a second time. When it's requested for the first time, Akamai adds it to a bloom filter. If it's seen again, then the file is cached.
4. Databases like Cassandra, HBase, RocksDB use bloom filters for each SSTable. It helps to quickly verify if a key definitely doesn't exist in the SSTable and skip it.
5. Services like Medium use bloom filters to track which articles a user has already read.
6. During broadcast join in Apache Spark where a very big table is joined with a much smaller table, the smaller table is broadcasted to all the executors. Spark builds a small bloom filter for the smaller table on the join key and broadcast it. It enables the executors to filter out all the rows that definitely don't have the matching key. Only a smaller percentage of rows from the big table then can participate in the join operation.
